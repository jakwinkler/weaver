# Automatic Time Privacy Threat Model

- Status: Phase 7 local-alpha review
- Date: 2026-08-31
- Scope: macOS companion, device pairing, draft synchronization, correction learning, plugin disable, and plugin uninstall

## Security objectives

Automatic Time must keep raw work context on the Mac, keep private drafts scoped to their owner, and require an interactive Weaver user to create official time. A paired device may propose private drafts, but it must never gain release authority.

The model protects:

- window and browser titles, application context, repository paths, Git metadata, and local activity intervals
- the local evidence-encryption key and device bearer credential
- private drafts, correction memories, review events, and local-alpha metrics
- official time entries and their lock, idempotency, and ownership rules

Screenshots, screen recordings, audio, keystroke contents, clipboard contents, file contents, and page contents are outside the data model and must never be captured.

## Trust boundaries and data flow

1. macOS collectors read only the enabled metadata sources. Optional window-title and browser capture remain permission and settings gated.
2. Raw signals, activity blocks, candidate snapshots, correction memories, outbox entries, and deletion tombstones are stored in an owner-only AES-GCM encrypted local store. The encryption key and device credential are stored separately in Keychain.
3. Segmentation and assignment run on the Mac. Optional semantic ranking is restricted to a loopback endpoint.
4. Pairing begins with a short-lived secret generated for the companion. An authenticated Weaver user approves the displayed user code. A successful one-time exchange returns a scoped device credential.
5. The companion sends derived drafts over HTTPS, or plain HTTP only when the API host is a loopback address. Requests include the tenant ID and the scoped bearer credential.
6. The plugin stores private drafts and correction state in plugin-owned tenant tables. Every browser operation is bound to the interactive user. Device routes derive the user from the valid device credential.
7. Only an interactive browser release can call the core time-entry capability. Device routes do not expose release.
8. Disable revokes every active plugin device credential. Confirmed uninstall deletes plugin-private tables while preserving core-owned official entries.

Uninstall does not erase companion-local storage, as described above.                                                                                                                                   |

## Phase 7 verification map

- Companion unit tests cover exact retention cutoffs, encrypted restart recovery, credential expiry and revocation, correction-memory revision recomputation, remote-HTTP rejection, and the derived-draft network contract.
- API integration tests cover hashed one-time pairing, expiration, scopes, immediate revocation, unknown-field rejection, correction-memory ownership and reversal, local-alpha aggregation, release authority, and uninstall preservation.
- Web component tests cover private metrics plus correction-memory inspection, disable, recompute, and deletion controls.
- The ten-working-day alpha remains the required runtime evidence for capture reliability, real review time, real assignment quality, and manual-timer displacement. Synthetic and automated tests do not satisfy that trial.

## Open findings before broader distribution

1. Replace unsalted correction-context hashes with a keyed device-local digest if the server will be operated by a party other than the user.
2. Verify signing, notarization, Keychain access groups, Accessibility permission behavior, and upgrade behavior on the exact distributed companion artifact.
3. Add a documented companion removal action that deletes the Keychain items and local Application Support store when the user chooses to remove local data.
4. Decide a retention limit for long-lived review events and local-alpha aggregates after the ten-day trial.

No open finding grants broader capture or release authority. The first local alpha remains single-user, local, disabled by default, and subject to explicit review and release.
